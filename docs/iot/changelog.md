# Changelog API IoT

Semua perubahan pada `/api/v1` dan payload `POST /api/ingest` dicatat di sini, yang terbaru di atas.

## Belum dirilis

- Menambahkan role undangan `partner` dengan akses sesi hanya untuk Developer/profile dan key Test milik sendiri tanpa scope `admin`; menambahkan `areaRef` ke pratinjau QR publik dengan redaksi privat tetap berlaku. Hard maximum TDS kini 1000 ppm di firmware, API, dan data lewat migration 007; warning tetap 400/900 ppm. Inventaris saat ini: 3 perangkat satu-sensor dan 1 paket dengan ESP32 DevKit V1, PH-4502C, DS18B20, dan TDS Meter V1.0.

- Memperbaiki validasi pola kode tipe yang gagal di Chrome 155; kontrak API tidak berubah.

- Koreksi dokumentasi ingest legacy setelah membandingkan route: payload v1 dengan `measuredAt` sebelum `credential_since` menghasilkan HTTP 401 (`REQUEST_REJECTED`), sedangkan payload v2 menghasilkan HTTP 400 (`VALIDATION_FAILED`). Tidak ada perubahan route atau perilaku API.

- Minggu 4 A: `/docs` menampilkan Scalar dengan asset lokal dan spec aktif yang tetap tersedia publik di `/docs/openapi.json`. OpenAPI kini memuat autentikasi, scope route, contoh request/response, serta error sesuai implementasi. Koreksi dokumentasi terhadap route aktual: status write jenis sensor/tipe device dan response tanpa body `204`, media QR SVG/PNG, daftar device maksimal 100 item dengan `cursor` yang belum dipakai (`nextCursor` selalu null), field `name`/`unit` pada overview, dan ingest v1 legacy bersama v2 satuan/paket. Tidak ada perubahan route, payload, seed, atau perilaku pilot.

- `GET /devices/:id/readings?bucket=raw` kini menerima filter sensor opsional, menyertakan state tiap pembacaan, total dan metadata aman pada halaman pertama, serta cursor deterministik. `GET /devices/:id/readings/export` menghasilkan workbook XLSX dua sheet dengan ringkasan SQL dan streaming ber-batch, dibatasi ownership/environment, jumlah baris, laju request, dan ekspor bersamaan.

- Klarifikasi kriteria Test Plan sejak baseline `7798e12`: V1-14 menetapkan bahwa `POST /api/v1/devices/claim` dengan key Test dan tanpa Origin tetap menghasilkan `404 NOT_FOUND` karena resource sandbox tersembunyi, bukan karena Origin ditolak. V1-18 menetapkan klaim serentak atas device live yang sama oleh dua akun menghasilkan tepat satu HTTP 200 dan satu HTTP 409. HW-08 kini mencantumkan reprovisioning dengan credential baru dan penolakan `400 VALIDATION_FAILED` untuk record buffer dengan `measuredAt` sebelum `credential_since` baru; observasi fisik state Halted/LED tetap menunggu bench.

- Frontend Monitoring: sebelum refactor, setiap refresh sidebar per 60 detik mengirim 7 request, yaitu satu `GET /devices` dan enam `GET /sensors/:code/overview`, satu untuk setiap kode katalog (`ph`, `tds`, `water_temperature`, `ec`, `air_temperature`, `humidity`), termasuk tipe sensor yang tidak dipakai device. `GET /sensor-types` mengambil katalog sekali saat startup. Implementasi lama di `src/components/SmartSidebar.jsx` dan enam seed di `server/migrations/002_iot_platform.sql` menjadi dasar hitungan tersebut. Poll mandiri sidebar dihapus; sidebar kini membuat lease pada snapshot katalog/overview bersama Monitoring dan menerima update SSE. Cache per pengguna berlaku 5 detik; latest mengambil overview per kode sensor yang dipakai device; histori paket dimuat saat kartu terlihat dan dibatalkan saat keluar/unmount; Per area hanya berjalan pada tab aktif. Seluruh request tab memakai governor klien kapasitas/refill 50 per menit dan cap ketat 50 per jendela bergulir 60 detik dengan prioritas user, latest/katalog, histori, lalu area.
- Frontend stream: setelah stream yang pernah tersambung berhasil reconnect dengan HTTP 200, setiap subscriber me-refresh nilai latest tepat satu kali. Koneksi awal dan response gagal tidak memicu refresh; replay tetap hanya untuk `device_event`, bukan `reading`. Tes mencakup refresh reconnect, deduplikasi replay, dan pembatalan fetch serta reader saat subscriber terakhir dilepas.
- Koreksi alur login QR: Shell mempertahankan `/d/:code` tervalidasi saat sesi berubah menjadi authenticated di `/masuk`, dan form Login menangkap tujuan sebelum menunggu respons. Redirect tetap memakai satu path internal; tujuan lain kembali ke halaman utama sesuai peran.
- Koreksi E2 frontend: refresh Per area berjalan tiap 5 menit saat terlihat dengan tombol manual dan sub-anggaran 60 request/menit. Record sandbox yang diizinkan API ditandai dan tetap tampil pada Monitoring/Detail; sandbox tetap dikecualikan dari area dan badge perhatian.
- E2 frontend: Monitoring memakai tiga tab kategori (Per paket, Per sensor, Per area) dengan panel Log kejadian di samping pada desktop dan di bawah pada layar sempit, seluruhnya memakai overview/readings/events dari kontrak yang ada. Statistik area memakai tengah malam lokal serta rata-rata berbobot jumlah sampel; badge perhatian menyembunyikan nol, mengecualikan sandbox, dan menghitung device live berbeda yang offline atau memiliki sensor low/high (termasuk device stale yang memiliki alert). Developer menyediakan panel sandbox melalui subscriber stream bersama. Kode aktivasi QR kini hanya berada di memori dengan TTL 10 menit dan dibersihkan saat klaim berhasil atau logout dimulai.
- Koreksi E1: fetch streaming mengirim `Last-Event-ID` dan menerima replay gap dengan deduplikasi ID; fallback polling kini mencoba pulih dengan backoff dan menghormati `Retry-After`, tanpa penambahan endpoint atau query Contract. SSE mengirim komentar `: connected` segera setelah header 200 di-flush agar fetch client di balik proxy melihat respons sebelum replay/heartbeat. Singleton membersihkan semua resource setelah subscriber terakhir dilepas.
- Minggu 3 sandbox: migration 005 menambah sequence kode dan pemetaan satu device virtual per akun. Provisioning test key dan GET daftar sandbox oleh sesi/key idempoten, termasuk sesi tanpa key test. Runner 30 detik non-overlap; cleanup retensi dalam runner berjalan saat startup lalu tiap 24 jam. Cleanup hanya menyentuh sandbox, mempertahankan event threshold terakhir per sensor dan event koneksi terakhir per device; batas pilot tetap 20 unit live.
- Minggu 3 backend: SSE satu instance memakai satu ID dari `device_events.id` hanya untuk frame `device_event`. Frame `reading` tidak ber-ID, replay memakai filter akses actor yang sama dengan pengiriman live, heartbeat 25 detik, dan batas 5 koneksi per actor; koneksi keenam mendapat 429 `RATE_LIMITED`. Ingest dan job offline publish setelah commit, dan duplicate/rollback tidak mempublish. Endpoint events memakai cursor Base64URL dari ID dan urutan `id DESC`; `at` bukan urutan karena event ambang memakai waktu ukur.
- E1 frontend/API: List IoT dan Detail device memakai latest, riwayat, kejadian, serta SSE dengan polling fallback 30 detik. Daftar dan detail device menyertakan `credentialProvisioned` non-secret (`credential_hash IS NOT NULL`); Kelola IoT hanya menampilkan rotasi untuk device live yang terprovisioning, lalu mewajibkan salin atau pengakuan penyimpanan sebelum dialog secret satu-kali ditutup.
- Langkah D backend: `POST /devices/:id/credentials/rotate` hanya untuk scope admin dan device live terprovisioning. Path menyimpang dari prompt singular `/credential/rotate`; dipilih `credentials` sebagai namespace subresource rotasi, dan adapter harus mengikuti path kontrak. Device belum diprovisioning (`credential_hash IS NULL`) menghasilkan 409 `CONFLICT`. Hash serta `credential_since` diganti atomik dengan row lock yang sama seperti ingest; credential baru hanya ada di response rotasi, credential lama langsung 401 sesudah commit, dan buffer lama sebelum `credentialSince` ditolak 400. Operasi credential, release, claim, aktivasi, serta QR terhadap sandbox mengembalikan 404 `NOT_FOUND`.
- Minggu 3 backend: menambahkan migration 004 untuk skenario sandbox dan indeks state event; menambah latest/readings/overview, ambang area, events, transisi threshold, serta deteksi offline. Ingest v1/v2 dan job offline mengunci baris device yang sama agar tidak menggandakan atau membalik event koneksi. Evaluasi ambang hanya memakai reading terbaru menurut `measured_at` dan `messageId`; event threshold memakai waktu ukur. Deteksi offline dapat dimatikan dengan `OFFLINE_DETECTION_ENABLED=false` untuk test.
- Minggu 2 frontend: pemindai QR di aplikasi kini membaca QR di mode development. Loop deteksi sebelumnya berhenti permanen setelah effect dijalankan ulang oleh React StrictMode.
- Minggu 2 frontend: halaman `/d/:code` menghapus parameter `c` dari address bar setelah dibaca, dan halaman dikirim dengan `Referrer-Policy: no-referrer`. Isi QR tetap `/d/<code>?c=<kode aktivasi>` sesuai API Contract 6.3. Dev server Vite menerima host tunnel HTTPS lewat `DEV_ALLOWED_HOSTS` khusus development; validasi `APP_ORIGIN` di backend tidak berubah.
- Minggu 2: usulan limit gagal autentikasi API key 20 per IP per 60 detik untuk key berformat valid yang salah atau dicabut. Setelah penuh, key berformat valid dari IP tersebut mendapat `429 RATE_LIMITED` sebelum lookup sampai jendela reset; key valid tidak menambah penghitung tetapi ikut tertahan, termasuk pengguna lain di jaringan NAT atau kampus. Key malformed/non-API, sesi cookie, scope 403, dan error 5xx tidak menambah penghitung. Limit API lama tidak berubah.
- Minggu 2: pembuatan API key mensyaratkan minimal satu scope; request dengan `scopes: []` ditolak sebagai `400 VALIDATION_FAILED`.
- Minggu 2 frontend: Kelola IoT menggunakan route yang tersedia. Aksi Nonaktifkan pada screenshot 04 disembunyikan karena API belum menyediakan field atau route; tidak ada perubahan kontrak API. Area hanya memakai `areaRef` aktual atau isian manual. Developer memakai data key dan usage aktual, tanpa panel Sandbox atau statistik contoh.

- Minggu 2: pengelolaan API key lewat sesi cookie, secret hanya dikembalikan saat pembuatan, prefix dan hash SHA-256 yang disimpan, pencabutan langsung, kebijakan role, serta ringkasan usage tujuh hari.

- Minggu 2: key `test` dibatasi ke device sandbox dan key `live` ke device non-sandbox, dengan isolasi ownership dan response 404 untuk resource yang tidak dapat diakses.
- Minggu 2: rate limit API key 60 request/menit untuk `live` dan 30 request/menit untuk `test`. Usage dan `last_used_at` dicatat secara non-blocking dengan route template Fastify. Query retensi 30 hari didokumentasikan, belum dijadwalkan.
